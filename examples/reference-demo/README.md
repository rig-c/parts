# reference-demo

**A fixture, not on display.** This character was published as `demo` and was the
README's picture until issue #227, which took it off display: its clasped hands do
not read as hands at full size. It stays here, under this key, because its
`expected/` is the reference implementation's own output and the selftest's chain,
scene and auto-mesh suites hold this port to it. Its `config.json` keeps
`"key": "demo"`: the reference named its skeleton after the key (`demo_painting`), and
`expected/` carries that name. The display `demo` is a different painting
(`examples/demo`).

`expected/rig.json` is the flat form: every bone unturned, which is `flattenRig`
(`src/rig.ts`) of the built rig and the form the reference implementation wrote. A
build's `rig/rig.json` turns each chain link along its chain, so it carries `rotation`
and `length` on the links, and the offsets under them in the turned frame, where this
file holds unturned offsets only: a plain diff of the two shows those bones and the
weights bound to them as changed, and the build is not broken. The chain suite (`CH03`)
compares this file with `flattenRig(built)`, not with the built file; compare the same
way.

pink frilled idol dress, with very long twin tails, a large ribbon hair bow, a

`meshes`, `regions` and `motion` are the proposal's, unedited, while
`seethrough.head_box` and the `hair_back` plan entry carry the reference run's
two input-stage corrections), `proposal.json` (what the proposer wrote — the
`propose` stage — but for its first two notes, the head frame and pitch
this port adds, issue #250), and under `expected/` the reference implementation's

with every reference value left as it was), `rig.json` (the reference's, whose bones are all unturned; this port turns each chain link along its chain — issue #73 — so the built rig is compared through `flattenRig`, which turns every offset back, and matches it exactly), `motion.json` and `mesh_report.json` (`rig`), and

## What the README showed

Until issue #227 the README's first picture was this character, built with
`rig-parts build --seam silhouette --loop` from the tracked config. The figures
it quoted, kept here with the fixture they describe:

- Two input-stage edits by hand for the reference run this example reproduces: the
  head box shifted down into the canvas (its proposal ran 118 px above the top edge;
  `propose --head-box` now makes that shift itself), and `hair_back` taken from the
  full run, because the twin tails leave the head crop sideways (a plan edit).
- `check` printed, verbatim:
  `50 assertions: 24 measured (24 passed, 0 failed), 26 skipped, 0 not in profile "rig-play"`;
  `loop: idle 49 frame(s) at 12 fps, f0000 vs f0048 (t = 4s): max |d| 0 (0 required)`;
  `seam: setup pose at 714x1216, scale 0.9422: mean |d| 0.234 (<= 1.0), 2 px over 40, 2.25 rig px (the count / s²; <= 50), 0 px over 80 (reported)`;
  `pack: skeleton.png 922x1348, 22 region(s), 94.9% covered, padding 2, page edges free, shape polygon`.
- `--seam silhouette` repaired the navy blobs the default rule leaves on the white
  blouse (recomposite error pixels 10,340 → 8,644).
- The loop: `rig-parts loop --palette`'s indexed APNG, 48 frames at 12 fps,
  1,706,719 bytes, one 256-entry palette at max 57, mean 1.601 per channel (the
  lossless APNG 13,645,503 bytes; the GIF 1,812,288). Frame 29 (2.417 s) is the
  closed eye: the blink holds for 0.084 s, where the reference implementation held
  0.04 s and no frame of its loop showed the eyes shut (issue #32).
